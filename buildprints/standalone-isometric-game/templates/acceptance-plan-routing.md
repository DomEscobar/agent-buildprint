# Instantiate the upstream v3 plan — do not invent a schema

Read the pinned isometric-visual-loop `references/acceptance-plan.example.json` and `acceptance.md`. Use that COMPLETE version 3 example as the technical starting point in the host; do not copy a neutral example scene or pretend its market/river IDs are this game's content. No filled acceptance JSON is shipped here because no game contract exists yet.

1. Create `.game-quality/acceptance-plan.json` with `version: 3`, `root: ..`, `contract: PROJECT_CONTRACT.md`. Derive `requirements` IDs/domains/descriptions/views from every approved outcome, and `comparisons` for every visual requirement/view using real protected target paths and declared reference roles.
2. Set `inputRoots` to actual host source, maps/assets, runtime files, build/config/lock inputs and contract. Keep receipts, tickets, captures and reports outside these roots. Do not hash a directory that contains its own changing evidence. Include source-to-render exporters so passing sidecars cannot drift from the running host.
3. Select genuine `reviewMode` before freezing; unavailable independence is disclosed. Derive `artChecks` and packed-art groups from the real loaded manifest, ALL promised facings/actions/overlays, intended bounds and decoded geometry. Empty art checks are not a loophole for a raster game.
4. Populate `production.version: 1`, applicable `rigidAssets`, and all six stages' `checks`. Read the upstream schema for `id`, `stage`, `method`, `requirements`, `views`, `inputs`, `evidenceKind` and conditional layout/art fields. Final checks cover all input roots. Geometry checks bind measured art to actual host exports; layout scope protects every required region/instance/route/bridge ID.
5. Adapt the upstream semantic layout v1 example only as technical topology data. All required collections exist (empty only where truly absent). Layout drives real host placement/collision. Flat axis-connected checks do not prove multi-floor links, slopes, subcell geometry, alpha or rendered water width: keep promised geometry and supplement with host-specific evidence.
6. Use `.game-quality/baseline.json` for the upstream freeze and `.game-quality/production-receipts/` for upstream receipt outputs, matching `runtime.json.productionEvidence`. Never create these as auto-passing templates. Review the contract-to-plan translation for complete scope BEFORE freeze. Populate target references and art specs; runtime inputs may be produced later as upstream permits. Begin eligible checks before work/evidence. Use upstream-generated drafts/receipts rather than hand-copying hashes or auto-passing templates.
7. Preserve protected thresholds, targets and requirements. Rebaseline only for documented authorized changes/corrections, retaining prior failures and coverage under upstream rules. A completed calibration never removes future art groups or content from final acceptance.

This outline is authoring guidance, not a new tool/API. All exact commands/fields come from the pinned framework references. Packet checks and synthetic runtime tests do not establish game validation or acceptance.

## Noncompensable measured assembly requirement
Include `assembly-measured-geometry` in the protected plan (visual domain, agreed calibration views), assembly review and later static/final coverage. Loop 02 requires its explicit per-requirement verdict through the existing `agb/receipt/v2` coverage seam. Link a populated `templates/measured-geometry-review.md` report as a review artifact alongside unedited captures and actual upstream receipts. High aesthetic scores, parity, a bounding box or an inverse-fitted zero cannot turn a failed/unverified requirement into pass. A required report that cannot be independently measured remains unverified and blocks assembly advancement.

The report is packet review format version 1, NOT new fields in upstream art-contract v1 or production v1. The pinned framework checks annotations/bindings; it does not independently select raster endpoints or compute their pixel/model residuals. The CLI enforces recorded verdicts and receipt linkage, not report semantics. An executable independent-pixel checker belongs in the separately pinned framework and is **not implemented here**; any contract requiring that automated capability remains blocked pending separately verified upstream work. No pin bump or metadata pass supplies it.

Keep measurement, experience, aesthetic, required human acceptance and release permission as separate requirement IDs/decisions, never a compensating aggregate. User acceptance pending permits only an otherwise authorized inspection preview, not accepted production. Setup receipt records active test discovery separately from hash input roots.
