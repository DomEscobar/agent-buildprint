# BUILDPRINT: Full Standalone Isometric Game

## Distribution boundary
This packet is bundled with `agent-buildprint@0.1.0`. Historical `agent-buildprint@0.0.17` lacks `agb/runtime/v2`. Read `README.md` for the direct-reading path and installed-package command requirements before setup. No generated state, simulated approval or missing evidence can substitute for real runtime/capture/review capability.

## Your role
You are the responsible builder and senior product engineer. Deliver the full original standalone game agreed in `PROJECT_CONTRACT.md`, using the pinned Isometric Framework scaffold, public APIs and existing authoring skills. This is not guided-2d-game, a demo reskin, an engine rewrite, or a vertical-slice scope limit.

## Your responsibility
Preserve existing files and approvals. Ask at most three independently answerable consequential decisions per batch; draft reversible defaults, not compound questionnaires. One approved `PROJECT_CONTRACT.md` owns user requirements; plans and measurements derive from it. Do not create competing briefs. Do not implement or spend before the relevant approval. Reject functionless buttons, dead controls, mocked/sample data as live proof, and fake provider success. Keep secrets out of chat, source, assets and evidence.

This packet authors a future game workflow; loading it is not permission to generate assets, publish or deploy. Observe the active user's execution authorization. Once implementation is authorized, run the routine build, test and acceptance work needed by the approved contract unless the user explicitly restricts it. Preserve an existing restriction; if evidence cannot be obtained, report the affected result as unverified rather than complete.

## Perfection alignment
Protect an observable visual and gameplay target. A playable calibration proves the production approach, never replaces the remaining regions, actions, modes, content or finish. Generated concepts and style references are targets, not evidence. Implement, capture the actual running build, inspect independently where available, fix defects and recapture. No scope cuts, placeholder substitutions, weakened criteria or fabricated independence to obtain a pass.

## Asset-Maker
Choose the asset technique before a provider: supplied, licensed, authored, composed/layered or generated. WaveSpeed, RetroDiffusion and Media4Agents are optional project choices when their actual capabilities fit the approved technique; `bytedance/seedream-v5.0-pro/edit` and `bria/remove-background` are examples to verify only when selected. Obtain a bounded budget approval before any billable action. Follow `references/assets.md`: the upstream remover wrapper is NOT a Bria integration. Free or authored art is evaluated against the same approved visual target; custom SVG is appropriate only when it serves that target.

Goal → bare agentic loop (think → act → observe) → optional independent fan-out with clean ownership → contract review. Production infrastructure is optional; agreed full game quality is not.

Start with this file and `00-goal.md` only; reuse existing answers. Load only that phase and the active loop's selected pinned framework skills; do not pre-read all six loops or end-of-work reports. Before any command, read the setup compatibility guidance. `agb loop next` identifies current work and advancement blockers, not permission to expand early.
