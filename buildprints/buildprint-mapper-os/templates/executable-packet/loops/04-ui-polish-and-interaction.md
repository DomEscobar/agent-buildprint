# Loop 04 — UI Polish And Interaction

## How to implement this loop

Before writing code, read:

- `loops/loop-flow.md`
- `.buildprint/next-agent.md` if it exists
- current project `AGENTS.md` if it exists
- `BUILDPRINT.md`
- `00-goal.md`
- `01-setup.md`
- `02-identity.md` and generated `docs/ui-identity.md` / `docs/DESIGN.md`

If the artifact is `not-ui-bearing`, rewrite this loop as operator UX polish (CLI help, logs, error copy, recovery) with the same anti-slop bar.

## Building objective

Keep `02-identity.md` open. Make the primary surface match the identity: metaphor, primary gesture, tokens, states, and motion. Every visible control must work or block honestly. Empty/loading/error/blocked states must be real. Desktop and mobile proof apply when responsive use is in scope.

Replace template genericism with the mapped product's interaction language: name the dominant object, the primary gesture, and the next powerful user action after first paint. Repair cramped mobile composers, dead chips, proof-console leakage, and raw JSON-as-UX. When identity forbids a silhouette, prove the shipped first viewport is structurally different — not merely recolored. Operator-only artifacts should polish CLI help, logs, error copy, and recovery with the same honesty bar.

## DO NOT

- Do not ship placeholders, functionless buttons, or mocked/sample data as live proof.
- Do not treat raw JSON as the main UX when a product surface is required.
- Do not claim distinctive UI from palette/copy swaps alone.

## Minimum proof before moving on

- Screenshot or browser inspection of the primary path.
- Confirm controls work or block honestly.
- Compare against identity anti-generic rules.

## Handoff note

Record UI proof, remaining craft debt, and blockers.
