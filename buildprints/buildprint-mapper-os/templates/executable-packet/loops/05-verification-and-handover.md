# Loop 05 — Verification And Handover

## How to implement this loop

Before writing code, read:

- `loops/loop-flow.md`
- `.buildprint/next-agent.md` if it exists
- current project `AGENTS.md` if it exists
- `BUILDPRINT.md`
- `00-goal.md`
- `01-setup.md`
- `02-identity.md`
- prior loop handoffs

## Building objective

Keep `02-identity.md` open. Re-run the meaningful proof paths for the goal, update the product-facing `README.md` to match what actually exists, prepare evidence for independent `review.md`, and write an honest `HANDOVER.md`.

Collect command results, screenshots or API transcripts, and acceptance-criteria status from `00-goal.md`. Name what remains unproven and which maturity upgrades are explicitly not claimed. Separate `loop_core_passed` from `claim_qualified`. Do not invent evidence ledgers or claim-gates JSON products. The handover must be concrete enough that a fresh agent can continue without re-discovering the repo.

## DO NOT

- Do not ship placeholders, functionless buttons, or mocked/sample data as live proof.
- Do not self-certify completion without scheduling independent review.
- Do not overclaim live/provider/deployment readiness.

## Minimum proof before moving on

- Re-run core proof commands or record blockers.
- Update README and HANDOVER.
- Hand off to `review.md`.

## Handoff note

List proof run, claim ceiling, blockers, and review readiness.
