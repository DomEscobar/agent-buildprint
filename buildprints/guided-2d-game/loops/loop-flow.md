# Loop flow

Goal → bare agentic loop (think → act → observe) → optional independent fan-out → contract review. Read the active loop only, plus its linked contracts, current runtime state and decisions. Independent workers need clean ownership; one owner integrates manifest and runtime changes.

## Parallel work, convergent proof
`01-gameplay-direction` and `02-art-motion` are independent entry tracks after their relevant setup decisions. The default active loop is a navigation pointer, not an art gate: select either track or alternate them; use separate workers only with clean ownership. Begin high-quality assets, art direction and approved provider work immediately or alongside gameplay. Graybox is optional for a specific mechanic question, never required before graphics, providers or animation iteration. `03-world-contract` consumes the art contract; `04-core-integration` joins all three completed contracts before release review.

Each loop’s minimum proof governs completion of that contract, not permission to work on an independent track. Use actual assets during mechanic tests when available; visual quality cannot replace gameplay proof, and gameplay testing does not require deliberately plain art. Keep iteration within the agreed content/spend bounds; approve representative feel and in-engine seed/motion before scaling content.

Before an edit, name its likely failures and the smallest proving path. After it, run affected tests and inspect the changed behavior. Asset change: decode/source-rect/anchor tests plus in-scene motion; placement change: shared validator plus affected routes and occlusion; mechanic change: state/input tests plus win/failure/restart. Run a full agreed slice campaign at convergence, integration and release milestones, not after every unrelated tweak.

Return to `00-goal.md` for changed scope, spend or rights. Return to `01-setup.md` for broken environment, loader or architecture. Return to `02-identity.md` for visual direction drift. Preserve working assets until replacement passes.

Do not create phase paperwork as the deliverable. Edits alone do not prove play. Do not fake live success. The generation request ledger exists only to control money and recover jobs, not as a second product or generalized evidence system. Use a compact milestone note and `review.md` before final completion. If independent review is unavailable, stop at loop_core_passed, not claim_qualified.
